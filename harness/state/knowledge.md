# Knowledge (core)

Gotchas that hold across every area of this repo, one line each. Area gotchas go in harness/state/knowledge/<area>.md (area names match the docs/READ_MAP.md headings). Keep this file under 12 KB; the planner's CONSOLIDATE mode merges and prunes.

- Every harness page is opened with ?debug=1&verify=1 (kit.config.json pageQuery). Debug UI must hide under verify=1 or it shows in every shot.
- A console.error fails verification. Use console.warn or nothing for expected situations.
- Wait on game conditions in sim time (window.__sim until/waitSim), never on fixed wall clock sleeps: a loaded machine runs less game per ms.
- Lessons from the old game are in harness/design/SALVAGE_AUDIT.md: section 5 (root cause of each base-layer failure) and section 8 (one-line rules). Read the rows for your area before building roads, terrain, tiles, physics or the bake.
- Dashboard: if http://localhost:4488/ answers 'missing dashboard', the running server is stale (started before a folder rename). Kill the process on 4488 and start node harness/bin/dashboard.mjs again.
- Verifiers always run in the snapshot (node harness/bin/snapshot.mjs, then work in .worktrees/verify), even with one agent at a time; otherwise their shots mix with the builder's and the dashboard verifier strip stays empty.
- GPU times on this Mac are only true while the GPU is busy: a Godot window is capped at 120 fps and a plain `gpuMs` under that cap is wrong (any scene under about 7 ms reads 6 to 7 ms).
- Never trust a plain `perf` reading when the frame is under 8.3 ms. `lookproof --perf` and the verify perf gate run the GPU ballast themselves; the long note (numbers, cause, the ballast tools) is in knowledge/rendering-and-look.md, "GPU time under the 120 fps cap".
- The player can be on foot (P1-022): code that reads the group "player" must not assume a vehicle (`has_method("foot_position")` is the vehicle test). Exactly one node is in that group at a time (`game/characters/player_mode.gd`), and `state().player.mode` says foot or vehicle.
- Never ask Anmol for animation clips or anything that needs Blender or Cascadeur: he cannot make them. Animation is builder work (authored poses, keyframed clips, IK, CC0 libraries). Model cards give no-skill steps only (AI text-to-3D plus Mixamo auto-rig) and are optional (Anmol 2026-11-13).
- The game boots into the streamed city (P1-024, scene `city`, full tiles): every scenario that loads another scene pays the city boot first (about 1.5 s), and `state().world` is set by default. Scenes for flat checks: `load('scaffold')` or `load('course')`; a city start elsewhere: query `spawn=<pin>` (game/data/spawn_pins.json).
- OSM is only the first reference (Anmol 2026-11-13, said several times): we build on top of it, remove what is wrong, add what is missing (side roads, dividers, subways), and change shapes and widths from real photos and satellite. Never treat an OSM shape or tag as correct just because it is in OSM; MAP_REPAIR.md and DELHI_WORLD.md have the rules.
- Quality bar (Anmol 2026-11-13): nothing the player sees is 'basic'. Every structure (tunnels, subways, flyovers, bridges, metro, rail) and every area must look finished and consistent with the signed look, built from real Delhi references and their local varieties (STYLE_BIBLE.md 'Infrastructure'). A plain box or bare wall is a placeholder and fails the task.
- Asset cards: never call a tool free unless its download is free too. Meshy generates for free but its model download needs a paid plan (Anmol 2026-11-13). Never ask Anmol to pay for anything; offer free routes or skip.
- Quality bar for streets (Anmol 2026-11-14): peak quality, matched to real photos, never empty. No 40 m of frontage without something real; every hero road has photo and game side by sides; emptiness found by the look audit is a blocker.
- Access and road use follow common sense, not only OSM tags (Anmol 2026-11-14): width, context (parks, monuments, campuses, bazaars, precincts, forecourts), surface and the judge pass decide who may use a way; OSM tags are one input.
- Restarting the dashboard: never `pkill -f harness/bin/dashboard.mjs`: another project on this Mac runs a dashboard with the same path. Find the kalesh one by its folder (`lsof -p <pid> | grep cwd`), kill that pid, start it again from the main checkout. A worktree's own dashboard (`HARNESS_DASHBOARD_PORT=<port> node harness/bin/dashboard.mjs`) shows that worktree's health.json.
- Worktree data/pilot_centre/ holds symlinks to the main checkout's source files (osm.json, overture_buildings.json, gedtm30_window.json, wikidata.json). Never rsync a worktree's data/ into the main checkout with -a: it replaces the real files with self-loop links and destroys them (happened 2026-11-14). To bring new source files back, copy regular files only: `rsync -a --no-links .worktrees/map/data/pilot_centre/ data/pilot_centre/`.
