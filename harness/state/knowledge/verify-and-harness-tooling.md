# verify-and-harness-tooling

One line per gotcha.
- task.mjs CLI tests run on a scratch copy with HARNESS_ROOT (see harness/bin/signoffs.test.mjs); a sign-off is one row in harness/bin/signoffs.mjs.
- A dashboard may already run on port 4488: test a changed dashboard with HARNESS_DASHBOARD_PORT=4499, or the old process serves the old /api/state.
- To change an open task's title, desc or acceptance use `node harness/bin/task.mjs edit <id> --desc-append "..." --accept-add "a|b"` (also --title, --desc, --accept to replace). Never hand-edit backlog.json.
- Godot: run anything through `node harness/bin/godot.mjs` (pinned binary). A `-s` SceneTree script must touch scene nodes on the first `_process`, not in `_initialize` (root not in the tree yet: "Cannot get path of node" errors). GDScript `%` has no `%e`. Godot colours output even into a pipe; godot.mjs strips ANSI before matching ERROR lines. A script error before quit() leaves the engine running forever, so pass `--quit-after`.
- `node harness/bin/godot.mjs frame <png>` takes one windowed frame through Movie Maker (about 12 s for 30 frames on the M2 Pro, Metal Forward+).
- Godot debug server: drive the game with `harness/bin/godotclient.mjs` (`launchGame`, `client.call`); `node harness/bin/godotsmoke.mjs` checks every hook in about 15 s. Godot's Metal driver reports 0 GPU ms; pass `--rendering-driver vulkan` (MoltenVK) when gpuMs matters. Per frame CPU time comes from `game/debug/frame_probe.gd` (`perf().cpuMs`), not `Performance.TIME_PROCESS`: it refreshes about once a second and includes the wait for the display under the 120 fps cap (about 9 ms for any scene).
- GDScript: a Node method named `_input` (or any engine virtual) with another signature is a parse error that only shows when the script loads; the debug server loads only with --debug, so run the smoke after touching game/debug/. `get_node_or_null("/root/...")` on a node outside the tree logs an error: guard with `is_inside_tree()`.
- Verify pages always have debug=1: to test the no-debug page, open the game URL minus the query in a same-origin iframe (harness/verify/scripts/hooks_no_debug.js).
- vitest: CLI tests that spawn task.mjs need a long testTimeout (30 s); under Godot load they pass 5 s.
- Godot target: page-side scripts run in a node vm (godotshim.mjs), so `D.input`, `D.hold({...})`, `D.setCamera` return before the game applies them; the next awaited request (`frames`) runs after them in order. Results from the vm are cross-realm: JSON-copy them before deep equality checks. Headless Godot never fires `frame_post_draw`: the debug server ends frames on `process_frame` there, and `perf` and `shot` answer an error.
- Never call `resolveGodot` (spawnSync `godot --version`) per run inside a driver that talks to other running games: it blocks the event loop. Pass `binary` to `launchGame`.
- lookproof.mjs runs on the driver of kit.config.json target (godot: one game run per view; `--query "style=x"` becomes `--style=x`); `perf.json` has machine, Godot version, renderer, GPU adapter and load. A `--approve` makes the set the reference: only run it after Anmol said yes.
- `npm run play` is playcopy.mjs --play: `git archive` of game/ at the newest verified commit into harness/reports/play/<sha>/ (gitignored), headless import, then a window run; extra args after --play go to the engine (`--quit-after 120` for a smoke run).
- vitest has no vite.config.ts any more: `vitest.config.ts` lists the test globs (tools/**/*.test.ts, harness/bin/**/*.test.mjs). A ?raw import in a test needs the `*?raw` module declaration in tools/geo/raw.d.ts for tsc.

- shoot.mjs `--args "--scene=street"` is dropped (parseArgs reads a value starting with -- as a flag): stage with `--load street` instead.
- A look proof view that holds the sim: settle first, then `{"call":"hold","args":[{"at":0}]}` (pauses at once) and a waitFor on `debug.clock().paused`; a settle after the hold never ends.
- `harness/reports/` is gitignored: bench reports in `harness/reports/arch/` exist only on this machine. Copy every number a design doc needs into the doc.
- Tools on this Mac (checked 2026-11-10): Blender, the osmium CLI, ffmpeg, clang, Python 3.14 and Node 22 are present; scons, cmake, cargo and GDAL are not. Install extras only inside the repo (a venv or an unpacked toolchain under `tools/`).
- The pinned Godot build is single precision, offers Jolt Physics and GodotPhysics3D (project on DEFAULT), FSR 1.0, FSR 2.2 and MetalFX in the viewport API, and has no built-in terrain or tile streaming (probed 2026-11-10; list in ARCH_OPTIONS.md "What is known before the benches").
- Godot windows and macOS focus (P0-033): on macOS the engine activates itself at launch and neither `display/window/size/no_focus` (override.cfg) nor `--position` stops it (measured: Godot frontmost about 1.2 s). godot.mjs `startFocusGuard` (used by `launchGame` and `godot.mjs frame`, off for headless and with HARNESS_FOCUS=keep) polls `lsappinfo front` every 25 ms and `open -b <bundle id>` brings the last Foreground app back: Godot is frontmost for only about 30-80 ms. lsappinfo and `open -b` need no Accessibility or Automation permission. Only apps of type Foreground are remembered (SystemUIServer flashes to the front). `npm run play` (playcopy.mjs) does not use the guard. Screenshots are byte-identical with and without it.
- Focus guard (godot.mjs startFocusGuard): acts only if a terminal app (TERMINAL_APPS, add more with HARNESS_FOCUS_APPS) was frontmost at launch, and only in the first 4 s; clicks on Godot later and runs started from another app are left alone (owner 2026-11-11).
- Architecture benches: `node harness/bench/arch.mjs <name>` runs the plan `harness/bench/<name>.plan.mjs` on the scene `game/bench/<name>/` (game arg `--arch=<name>:<tokens>`) and writes `harness/reports/arch/<name>.json`; `--list`, `--only a,b` and `--group g` (reruns merge into the report). Bench scenes answer the debug hook `bench(cmd, opts)` (`bench_call` on the scene root). The whole render bench takes about 20 minutes; it writes texture files to `game/bench/render/tex_gen/` (gitignored) and removes them at the end. Run it in the background with a log file: it is longer than the 10 minute foreground limit.
- zsh does not split `$var` into words: use `${=var}` when a loop passes a list of files to a script.
- Ballast (P0-039): `bench('ballast', {n})` and `bench('blank', {on})` are answered by debug_server.gd in any scene (`game/debug/gpu_ballast.gd`, shader `game/debug/ballast.gdshader`); `harness/bin/ballast.mjs` calibrates n (12 to 20 ms for a blank frame, cached per driver and size), takes a busy window and a blank window, and `ballastPerf` returns the plain perf block plus `gpuCost` ({ms, source, gpuP95, frameCostP50...}) and `gpuMsCapped`. perfgate.mjs already judges `perf.gpuCost.ms` as the GPU number. A perf window costs about 10 s more (calibration, busy, blank); lookproof --perf of 9 views takes about 2 min. Ballast frame cost and ballast GPU p95 agree within 0.3 ms. Triangle counts include the 4 shadow cascades. Why the plain window cannot be trusted: knowledge/rendering-and-look.md, "GPU time under the 120 fps cap".
- CPU benches in `arch.mjs` (P0-017): a setup with `gpu: false` skips camera paths and the ballast; its test runs inside the game (`bench('run', {test})`, then `bench('poll')`, because a hook call times out after 60 s) and the plan's `extra` stores the result. `project: {section: {key: value}}` starts that run with project settings: the runner writes `game/override.cfg` (gitignored) for the launch and removes it once the game answers; delete it by hand if a crash ever leaves it. The physics bench is 20 runs and about 14 minutes: run it in the background with a log. A test coroutine that hits a script error just stops: `runTest` in `physics.plan.mjs` watches the engine log for SCRIPT ERROR.
- DEFAULT for `physics/3d/physics_engine` is GodotPhysics3D on this 4.7.2 build, not Jolt (measured in P0-017 by the space state's class name), so `project.godot` names "Jolt Physics" (P1-006) and `test_sim_clock.gd` checks the running space state class starts with Jolt.
- GDScript: a loop variable over a literal array (`for s in [-1.0, 1.0]`) and anything read through a `Node` or untyped var is Variant, so `var x := s * 2.0` fails to parse ("Cannot infer the type"). Give such vars a type.
- Godot 4.7.2 off the main thread (P0-018 tile bench, no engine error over 21 loads each): `ArrayMesh.add_surface_from_arrays`, `ConcavePolygonShape3D.set_faces`, `PackedScene.instantiate` and `GLTFDocument.append_from_file` plus `generate_scene` all run on a WorkerThreadPool thread. `PackedByteArray.to_vector3_array()` turns file bytes into vertices in one call. GLTFDocument costs about 30 ms per file whatever its size. A node taken out of an instantiated PackedScene keeps its owner: set `owner = null` before adding it elsewhere or Godot warns.
- The headless renderer keeps no MultiMesh buffer (`get_instance_transform` reads zero): test placements from the bytes, not from the MultiMesh. A folder with a `.gdignore` (generated tiles in `game/bench/tiles/gen/`) is skipped by the import but `FileAccess`, `ResourceLoader` and `GLTFDocument` still read `res://` paths in it.
- Frame times in a bench window are not always capped at 120 fps: in the tile bench an idle frame was 0.5 to 2 ms with single idle frames of 4 to 24 ms. Judge a "worst frame" against the idle frames of the same run, and trust the timed main-thread step.
- `tsconfig.tools.json` follows imports from `tools/**/*.mjs` into `.ts` files, so it needs `allowImportingTsExtensions` too. A bake step before a Godot bench raises the host load: `arch.mjs` waits up to a minute for it to fall.
- Road bench (P0-019): `node harness/bench/roads.mjs` bakes both sites (about 1 s), then runs `arch.mjs roads` (two Godot runs, about 40 s; `--no-godot` skips it, `--only ito|cp`). A setup with `gpu: false, shot: false` takes its own shots in the plan's `extra` (one per pose from `game/bench/roads/gen/<site>.json`). Read `harness/reports/arch/roads/<site>_plan.png` first when a bake looks wrong: it needs no Godot run. A top pose is an orthogonal camera looking down with `look_at(target, Vector3(0, 0, -1))`, so north is up.
- Stitch bench (P0-029): retired in P1-008. `harness/bench/stitch.mjs`, `stitch.plan.mjs`, `stitch_draft.mjs` and the scene `game/bench/stitch/` are gone, so `node harness/bench/arch.mjs stitch` no longer exists; `harness/reports/arch/stitch.json` keeps its numbers. The architecture benches left are render, physics, tiles and roads.
- Float precision by eye (FP1): frames at a far place never equal frames at another place, so compare the same pan three ways: as baked, with the whole world moved so the place sits at the engine origin (`bench('rebase')`), and with a second move as the yardstick (a move alone shifts the shadow texels and changes edge pixels). Shimmer is what the far run adds over the yardstick.
- A water plane seen from below is not drawn (back face): a river missing from an eye level shot means the camera is under the water level. Godot node names cannot hold a colon: mesh names from a tile become node names, so the pins are `pin__<landmark>__<k>`.
- Perf scene kind (P1-005): a scenario sets `scene: "city"` (default look) and `lookproof --perf --scene-kind city` does the same; perfbudget.mjs `scenes.<kind>` overrides the preset for drawCalls, triangles and gpuMB (look keeps the quality preset first). Frame time, fps and load never depend on the kind; an unknown kind is judged as look with a warning.
- Godot tests may be coroutines (`run_tests.gd` awaits each test). `--quit-after` counts frames and a headless loop runs thousands a second, so godot.mjs test sets it far out and fails a run without the runner's `godot tests: N passed, 0 failed` line (before P1-006 an early quit read as a pass). The C1 replay test adds about 10 s of wall time (scale 0.25 runs 15 ticks a second).
- Module size tests: `game/tests/test_module_size.gd` (GDScript over 600 lines) and `tools/module_size.test.ts` (TypeScript over 800, read with `import.meta.glob` raw because tsconfig has no Node types; vite leaves the importing file itself out). Over-limit files go on the test's EXCEPTIONS with a task id; an entry back under the limit fails too.
- `verify.mjs --only <names>` runs typecheck and the whole test suite first (about 8 minutes with the pilot bake tests): add `--no-checks --no-build` while iterating on a scenario. Since P1-040 `flakecheck --runs N` (verify --repeat) runs perf and solo scenarios N times too, one at a time, before the pool.
- The Godot driver fails a run whose game dies while quitting (`godot crashed while quitting (exit code, signal)`, P1-019): before, an abort in the engine's cleanup showed only in the macOS crash logs (`~/Library/Logs/DiagnosticReports/Godot-*.ips`; the frames above `-[NSApplication terminate:]` are the quit path).
- A page-side script reaches a new debug hook only through `harness/bin/godotshim.mjs` (`SHIM_HOOKS` and the `debug` object); `bench` is not exposed to scripts. Script parameters come from JSON files (`data` of a script step), there is no per scenario argument.
- Debug server writes (P1-040): `StreamPeerTCP.put_data` blocks until the socket takes every byte, so a harness client that stops reading stalled the game (the stream_200 frames of 0.6 to 1.9 s with under 1.2 ms of game work). `debug_peer.gd` queues and flushes with `put_partial_data`. A paused node socket cannot show the bug (loopback buffers absorb seconds of snapshots): the smoke uses a python3 client with a 2 KB SO_RCVBUF (old server: one frame of 2054 ms).

- `frames timed out after 60000 ms` while `sample <pid>` shows the Godot main thread idling in `nanosleep`: the window stopped drawing (macOS stops drawing a fully covered window) while the sim runs on (a held throttle drove 700 m through the stall). Seen 2026-11-13 13:43 to 13:52 on old and new scenarios alike, gone after with no code change: rerun before debugging the game.
- Route following with real inputs (P1-024): `S.drive(points, {kmh})` and `S.walk(points, {gait})` in `lib/sim.js` press steer and throttle (or move and look) once a frame from `state()`, so they are allowed in milestone play scripts; run them with `lockstep: true` so every run steers the same ticks.
- City perf base (P1-026): `{script, params}` gives a shared script its scenario values (`window.__scriptParams`); lookproof views have a `group` (`--group`; a set named `city_*` takes the city group, any other the ungrouped look views), a city view stages with `teleport` (the vehicle stands there: put it behind the camera, or the debug camera sits inside its body) and a gali on foot with a script (F, then `S.walk`): `foot stage` places the body at y 0 in the city and it falls. `verify.mjs` overwrites `latest.json`, so `citybase.mjs` copies the city_path and city_base_systems results into `harness/reports/city_base/raw.json` on every run: run it after each verify. A single 33 ms frame with a 0.01 ms streaming core and a 10 ms process time is the present path or the OS, not the game: the city scripts only fail on long frames with game work in them.
- Owner 2026-11-14: agents' Godot runs must not show windows on his screen. shoot.mjs and verify.mjs launch Godot windowed; P2-032 ran them with `HARNESS_GODOT_ARGS="--position 30000,30000"` (off the screen if macOS does not clamp it; not confirmed), and closed its leftover window. A harness-wide off-screen default is a follow-up. `verify.mjs --only` also runs typecheck and the whole npm test first (1,200 s cap, hit under load): add `--no-checks` while iterating.
