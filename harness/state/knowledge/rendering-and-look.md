# rendering-and-look

One line per gotcha.
- Style tests restyle scenes from outside: game/render/style_runner.gd hooks SceneTree.node_added (connected in the GameArgs autoload _ready, before the main scene loads). Anything a style reads (mesh, metadata like "wear" or "facades") must be set on a node before add_child, and a style adds children with call_deferred (the node is mid-enter).
- Stand-in materials are matched by key: kit.gd materials() sets resource_name = key ("matte", "road", "satin", ...). People, signs and goods are all "satin", so grime only on "matte" and "road" keeps characters clean.
- Custom spatial shaders get raw vertex COLOR: convert sRGB to linear yourself (StandardMaterial3D does it via vertex_color_is_srgb). Per block values go in an `instance uniform` set with set_instance_shader_parameter.
- AgX (Godot 4.7) made the warm stand-ins grey and flat; Filmic plus a 3D LUT (ImageTexture3D, 33^3, built in code) and adjustment saturation gave "rich and warm". Golden light turns pink when an orange fog sits over a blue sky top: keep the golden sky top grey-warm.
- A Decal projects along its local -Y: for a wall with outward normal n use Basis(UP.cross(n), n, UP.cross(n).cross(n)) so texture rows run downward.
- Dressing a stand-in for a style test: the kit records dressing anchors with `Sink.anchor(kind, xf, data)` (windows, shops, roofs, tanks, lamps, vehicles, paths, the bazaar lane) and the builder commits them as node metadata `anchors`. Never consume the builder rng or add geometry for this: the default look must stay byte for byte. stylised_b builds the dressing with call_deferred, once every block (and its people) is in the tree.
- GDScript warnings are errors here: a property read through a `Resource`-typed var (`light.night`) is Variant, so `var x := light.night > 0.2` fails to parse; type it (`var x: bool = ...`).
- `Image.load_from_file("res://x.png")` prints an export WARNING; load the imported `Texture2D` and call `get_image()` (fallback to the raw file only before the first import).
- The first view of a fresh shader set can read a single-digit average fps while pipelines compile (a perf FAIL on car_closeup that a rerun does not show): judge perf on a second run, never the first after a shader change.
- SDFGI on the stand-ins (P0-038, Vulkan): the narrow bazaar lane reads near black by day and stays black after 12 s, with or without the dressing and with occlusion off; SSIL plus sky ambient plus a few soft bounce lights lights it well. Realistic keeps SDFGI opt-in (`--style-off=sdfgi_on`).
- ACES crushed the dark asphalt in shade to black at golden and dawn; the realistic look uses Filmic with exposure x1.25 and ambient x1.8. PhysicalSkyMaterial looked grey against the haze until energy_multiplier 2.2, turbidity 8, mie 0.01.
- Inverse square street lights (spot_attenuation 2) need energy about 170 from a 9 m head to show a pool on dark, damp asphalt under Filmic at night exposure.
- Shader uniforms and local variables share a namespace: a uniform `dust` broke a later `float dust` ("Redefinition"). `get_shader_parameter` returns null for a uniform the material never set, not its default.
- Upscaler test without a new game arg: realistic reads `--style-off=fsr2@0.75` (or metalfx@s) and sets Viewport scaling_3d_mode and scale; FSR 2 replaces TAA. MetalFX needs the Metal driver, which reports no GPU time.
- Godot import "fix_alpha_border" (on by default) bleeds colour into alpha 0 pixels: on a texture whose alpha is a mask (the tile_*.png layers) it smears dark lines into blocky bands (the "swirl cracks" and "marbled" walls of P0-034). Keep it off for mask textures, on only for real transparency (grille).
- Style perf (Vulkan, M2 Pro): shadow passes are the main cost of small dressing (wires, frames, grilles: put them on a no-shadow mesh); 40 small omni lights in a narrow lane cost about 2 ms; create night lights only when night >= 0.2; per-area volumetric fog (one FogVolume) about 0.3 to 1.3 ms; the full-screen heat shimmer pass about 1 to 2 ms. In the bazaar the sun's PCSS (light_angular_distance > 0) cost about 1.8 ms and directional_shadow_blend_splits about 1 ms; shadow triangles, splits and distance changed nothing measurable. Measure with --style-off tokens before guessing; run to run noise is about 0.5 ms on a calm machine and 2 to 3 ms when another process uses the GPU (check `ps -r` for browsers).
- Tiling textures in surface_b are `source_color`, so samples are linear: a 0.5 sRGB grey reads 0.21, not 0.5 (the asphalt `t.r * 2.0` multiplier is about 0.43 on plain asphalt).
- Look-proof run to run noise (stylised_b, same build, sim held, 1920x1080): golden and night mean diff 0.03 and 0.0% of pixels, afternoon (heat shimmer) 0.65 and 0.2%. `lookproof.mjs --approve` takes one set: golden is `approved/`, the other three lights are compared with `--against style_stylised_b_<light>`. look_rules.json tolerances are mean 1.5, share 1%.
- Per-instance shader uniforms (`instance uniform wear` in surface_b) have room for about 4096 instances (rendering/limits/global_shader_variables/buffer_size 65536, 16 slots each). Measured in P0-016: 5615 MultiMeshes that set wear, or 12000 MeshInstance3D nodes that only use the material, print "Too many instances using shader instance variables". Set wear on a few tile meshes only; instanced modules need another carrier (MultiMesh custom data or a per-area texture), or they draw with wear 0.
- Render bench (P0-016, `harness/reports/arch/render.json` summary, M2 Pro, 1920x1080, Vulkan, look B golden, GPU kept busy): the look alone 3.6 ms GPU (7.9 ms at 2880x1620); a 2 km city of 3877 buildings on MultiMesh cells with visibility range LOD 7.1 ms GPU, 1.2 ms CPU, 1600 draw calls; the same with no LOD 15.5 ms and 10600 draw calls; TAA plus 1.3 ms, MSAA 4x plus 1.55 ms; SDFGI plus 17 ms at 140 km/h (plus 2.4 ms on foot, plus 380 MB); 300 walkers plus 0.4 ms CPU and 0.8 ms GPU as 40 skinned plus baked vertex animation, plus 1.6 and 1.7 ms all skinned.
- Upscaling to 2880x1620 from a 1080p-class render (P0-016): FSR 2.2 costs 5.6 to 6.4 ms and MetalFX temporal 4.6 ms over the plain 1080p frame, MetalFX spatial 1.1 ms, FSR 1.0 1.2 ms, bilinear 0.5 to 0.7 ms. Native 2880x1620 is 14.7 ms. MetalFX is set through `Viewport.scaling_3d_mode` and works on the Metal driver in 4.7.2.
- VRAM compressed import on this Apple Silicon Mac (P0-016): with both project settings off the importer writes S3TC and the game loads S3TC; both sets on adds an ETC2 copy (cache times 2, import 2.8 s against 2.4 s for 30 megapixels); high quality (BPTC plus ASTC) took 63 s and 85 MB. A lossless texture array loads 40 times slower (839 ms against 22 ms) and takes 7 times the video memory (172 MB against 24 MB for one kit).
- A MultiMesh is culled as one box: every instance draws in every shadow split that touches the box (the baked crowd drew 4.0 M primitives against 2.8 M for 300 separately culled rigs). Keep cells small or turn shadows off for far instances.
- Default look (P1-002): with no `--style` the GameArgs autoload makes a stylised_b runner at boot, also under `godot -s` (autoloads load for SceneTree scripts): run_tests.gd calls `GameArgs.stop_style_runner()` first, and a test that makes a runner on the test tree must `stop()` it, or it restyles every node later tests add (stylised_b `_dress` errors). The engine adds the main scene to the tree before the autoloads get `_ready`, so a runner made in GameArgs._ready never sees the boot scene's node_added: GameArgs restyles `current_scene` with `restyle_tree` (earlier style tests only looked right because every view loads a scene). A preloaded script const named like an autoload (`const DayClock := preload(...)`) shadows the singleton and fails to parse: name it `DayClockScript`.
- The day clock rebuilds the style on a scene load (a move of a game minute or more) and, since P1-028, relights a loaded scene live in place (`style_runner.gd` `relight_to_clock`); a pinned clock never moves, so look proofs stay byte for byte. Look proof sets of the default look need `--query "time=<h>"` (or light=), else the shots carry the clock's hour at load. The flat look baseline is `--query "style=none"` now.
- Live relight rules (P1-028): anything a style derives from `light` must be set again in `light_environment()` / `_relight_materials()` (a field a day build never touched gets its Environment default back: ambient colour black, sky contribution 1). Night lights a live look makes ahead are drawn with a second rng (`_r2`): never add a draw to the main dressing rng, or the day and pinned looks move. The grade LUT costs about 10 ms in GDScript: a running clock builds it on a worker thread (quantised), a pinned jump at once. `state().time.live` has the counts.
- Flat StandardMaterial3D colours (scaffold ground, the city's tile stand-ins) read near white under stylised B's exposure: mark them `flat_stand_in` (metadata) and the style gives them a darker twin (`stylised.gd` `flat_gain`, light colours only; darkening asphalt too made the lampless city night road near black). The scaffold opts out of the heat shimmer (WorldEnvironment metadata `no_heat_shimmer`): on its long plain edges the wobble read as broken geometry.

## GPU time under the 120 fps cap

Since about midnight of 2026-11-11 (IST; the cause is not known, it was not so for the P0-009 baseline) a Godot window runs at 120 fps at most even with `--disable-vsync` (Vulkan and Metal), and under that cap the reading is wrong, most likely because the Apple GPU clocks down: any scene cheaper than about 7 ms reads 6 to 7 ms of `gpuMs` (the look B stack over an empty ground reads 6.6 ms and costs 3.6 ms). The stylised B readings of 6.5 to 6.7 ms (P0-037, perf_budgets.json "measured") were taken under the cap. For a true cost keep the GPU busy: the bench ballast (`harness/bench/arch.mjs`: `gpuP95`, or `frameCostP50` from frame times, which also works on Metal). Never trust a plain `perf` reading when the frame is under 8.3 ms. Since P0-039 `lookproof --perf` and the verify perf gate run the ballast themselves (`harness/bin/ballast.mjs`, `perf.gpuCost`, hook `bench('ballast'|'blank')` in any scene); stylised B re-measured: 4.0 to 9.0 ms, worst view per light 7.6 to 9.0 (perf_budgets.json `measured`). Cap cause: the Compatibility (OpenGL) renderer on the same window runs 600+ fps, so the cap is in the Metal layer present path of the Metal and Vulkan (MoltenVK) drivers, not a Godot setting (`--max-fps`, window size, Mobile renderer change nothing; fullscreen hangs the perf window); the cause is not found.
- City GPU base (P1-026, afternoon and golden, pilot tiles, stylised B, no dressing, ballast cost): 12 vehicle paths 3.0 to 4.0 ms at 60, 140 and 200 km/h, 160 to 370 draw calls, 0.15 to 0.55 M triangles, 185 to 197 MB video memory; look views 3.7 to 4.6 ms. The city costs far less than the bench city (7.06 ms, 1,609 calls) because the bake has shell buildings only: P2 dressing is judged against `perf_budgets.json` `measured.city_base`.
- `--light=<preset>` and `--time` were ignored in the city scene before P1-026: the boot scene is restyled from GameArgs._ready, before DayClock._ready read the args, so the style runner's `follow_clock` saw the default 15:00 clock and rebuilt the pinned light. It now returns while the clock node is not ready. Check a pinned light with `state().time.lookHour` (the hour the look was built for) next to `hour`.
- Infrastructure kits (tunnels, subways, flyovers, bridges, metro, rail, foot bridges) take their variant from `harness/design/reference/infrastructure/variant_map.json` and their size, colour and wear from the kind files there; facts are tagged [S] source, [P] photo, [E] estimate, and [E] values need a drawing or photo check before a kit is called final (P2-033).
- The look's depth fog (0.0026 to 0.0042 per metre) hides anything past about 1 km, so a far landmark needs its own haze: `game/world/landmarks/landmark_haze.gdshader` (render_mode fog_disabled plus FOG = the scene fog capped at 0.75, colour and density copied from the Environment every 0.5 s by `systems/landmarks.gd`). Use it from level 1 on (350 m, where the scene fog is still under the cap) so the level change does not jump.
- Infrastructure kits (P2-034): kit geometry in the stand-in materials takes the look's concrete texture only for low saturation greys (`surface_b.gdshader`: saturation under 0.09 and max under 0.78, e.g. #8c8a85); ballast is the `road` material (asphalt grain). A kit mesh's wear is the MeshInstance meta `wear`: above about 0.3 the wear mask shows brick and old paint patches on plain concrete, so flyovers use 0.15 and rail 0.45. Thin wires (3 cm) alias to dashes past about 150 m: keep them in the near level.
- Area kits (P2-010): `surface_b.gdshader` is a thin wrapper over `surface_b.gdshaderinc`; `kit_b.gdshader` compiles the same body with `#define KIT` (no `instance uniform`, so thousands of MultiMesh nodes may use it). Change the look in the .gdshaderinc and keep KIT blocks inside `#ifdef KIT`. In KIT the part code is UV2.x, the colour mode UV2.y; wall colour and wear are INSTANCE_CUSTOM (modules) or the shell's UV2 (rgb as a whole number, wear).
- A kit Texture2DArray is a vertical strip PNG with a hand-written `.import` (`importer="2d_array_texture"`, `slices/vertical=8`, `compress/mode=2`); the headless `--import` fills in the uid and both VRAM sets. Godot picks DXT1 for an atlas with no alpha (0.7 MB at 1024 px).
- Kit module cost (P2-010, Metal frame cost with the ballast, Chandni Chowk): module shadows off (5.3 M triangles and 5 to 6 ms with them). Measure A/B inside ONE game session (`stream('layers')` flat, param, rangeEnd, fade; scratch probe like city_buildings_busiest): the same build reads 2 to 4 ms across sessions, so one verify run proves little. What cost and what did not (attempt 2): baked noise (kit_noise.png, fbm in grey, value noise in alpha, one fetch each) plus flat packed varyings (world position and normal rebuilt from VERTEX and NORMAL) took about 1.5 ms; mesh LOD index buffers (module_mesh.gd detail levels) cut drawn triangles from 1.1 M to 0.4 M but saved little; dropping thin bars in the vertex shader, constant roughness, the range fade and backlight saved nothing measurable. Left: shells about 0.5 ms, modules with a plain grey material about 0.5 to 0.8 ms, the kit fragment body about 0.4 ms.
- Mesh LOD keys (module_mesh.gd lods()): Godot draws LOD i once key * view width / (distance * 2 tan(hfov / 2)) is under the 1 px threshold, distance from the camera to the MultiMesh's (125 m cell's) AABB, so the camera's own cell always draws LOD 0. An empty LOD must be one zero-area triangle ([0, 0, 0]).
- Afternoon sun clips lit walls brighter than about sRGB 190 to flat white; keep wall albedo under the wall_samples.json cap and scale a kit's colours together, never one by one (P2-010).
- Kit wall colours live in kits.json `walls`, made by tools/kits/sample_walls.mjs from board rectangles: change the rectangles, not the hex values (P2-010).
- The kit noise is an 8-bit texture: grime thresholds narrower than about 0.02 show texel steps; use smoothstep over 0.02 to 0.1 (P2-010).
- `verify.mjs --only` runs typecheck and the whole test suite (with a bake) first; use `--no-checks` for look iterations (P2-010).
- Sign board text (P2-048): sharp's SVG `<text>` on macOS uses CoreText system fonts and ignores FONTCONFIG_FILE and `fontfile`, so free fonts in the repo never apply; shape text with harfbuzzjs into SVG paths (`tools/kits/signtext.mjs`). Wikimedia thumbs only come in standard widths (960 works, 400 gives HTTP 400), and the API rate limits a burst of a few hundred requests: cache metadata and thumbs.
- Sign boards (P2-048): a board quad's vertex COLOR is data, not colour (r group, g slot, b flags); change the sign atlas layout in make_signs.mjs GROUPS, the shader SIGN_RECT/SIGN_GRID and kit_pieces.gd G_* together (test_area_kits.gd checks they agree). Night emission reads the project shader global `kit_night` ([shader_globals] in project.godot), set by stylised_b light_environment; with --style=none it stays 0 (day).
- Sign light (P2-048): the additive pool and wall spill quads (sign_pool.gdshader) use depth_test_disabled and a depth buffer check against the quad plane (normal component and side distance); without the side check the light shows through walls in front. A vertical sign's spill recomputes the kit shader's per-bay hash12 to light only glow cells.
- Kit pieces in one place on a bay (P2-048): give them a `slot` in kit_modules.gd PIECES (front, sill); their kits.json shares add up per slot and must stay at or under 1.
- Sign wear (P2-048 round 3): a mark must be about 8 texels wide or more to show at 10 m on the driving camera (a 2.7 m board is about 250 px wide there); size wear in metres (`make_signs.mjs` `PPM`) and pick the peel level by quantile, so the share of a board that has gone is the number you set. The atlas run takes about 90 s of CPU (6 minutes on a loaded machine): never start a Godot import while it writes (a half written PNG fails the import).
- Shell walls (P2-048 round 3): the shell material is one per kit (`module_library.gd` `shell_materials`: the hotel layers with the tile's main kit's sign atlas). Signs on shells are drawn in the kit shader from the facade UV; the bay width and floor height in metres come from the ratio of screen derivatives (wall metres over facade UV), taken outside any branch, and the atlas is read with `textureGrad` from the facade UV's own derivatives (a `fract()` UV gives mip seams).
- Shader `TIME` keeps running under the sim hold (the hold stops ticks and physics, not `Engine.time_scale`), but a forced draw with no frame step freezes it: the debug server draws covered or parked windows with `RenderingServer.force_draw(false, delta)` since P2-048 round 3 (before, with no step, nothing a shader animates moved in shots). A frame sequence waits on sim time and drawn frames (`city_sign_led.js`).
- Sign lettering (P2-048 round 3): a `stroke-width` on a `fitLine` group is in font units (the glyph paths are scaled by size over upem), so 1.6 draws a hair; pass `stroke` and `strokePx` to `fitLine`. librsvg (sharp) renders `feTurbulence` plus `feDisplacementMap`, which is the brush wobble of painted boards; size strokes and shadows by the fitted height (`fitLine(...).h`), not the asked size, or long names clot.
