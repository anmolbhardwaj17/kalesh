# rendering-and-look

One line per gotcha.
- Style tests restyle scenes from outside: game/render/style_runner.gd hooks SceneTree.node_added (connected in the GameArgs autoload _ready, before the main scene loads). Anything a style reads (mesh, metadata like "wear" or "facades") must be set on a node before add_child, and a style adds children with call_deferred (the node is mid-enter).
- Stand-in materials are matched by key: kit.gd materials() sets resource_name = key ("matte", "road", "satin", ...). People, signs and goods are all "satin", so grime only on "matte" and "road" keeps characters clean.
- Custom spatial shaders get raw vertex COLOR: convert sRGB to linear yourself (StandardMaterial3D does it via vertex_color_is_srgb). Per block values go in an `instance uniform` set with set_instance_shader_parameter.
- AgX (Godot 4.7) made the warm stand-ins grey and flat; Filmic plus a 3D LUT (ImageTexture3D, 33^3, built in code) and adjustment saturation gave "rich and warm". Golden light turns pink when an orange fog sits over a blue sky top: keep the golden sky top grey-warm.
- A Decal projects along its local -Y: for a wall with outward normal n use Basis(UP.cross(n), n, UP.cross(n).cross(n)) so texture rows run downward.
- Godot Metal reports no GPU time: style perf numbers from a plain lookproof --perf are CPU only (0.4 ms). Compare looks with HARNESS_GODOT_ARGS="--rendering-driver vulkan --disable-vsync".
- Dressing a stand-in for a style test: the kit records dressing anchors with `Sink.anchor(kind, xf, data)` (windows, shops, roofs, tanks, lamps, vehicles, paths, the bazaar lane) and the builder commits them as node metadata `anchors`. Never consume the builder rng or add geometry for this: the default look must stay byte for byte. stylised_b builds the dressing with call_deferred, once every block (and its people) is in the tree.
- GDScript warnings are errors here: a property read through a `Resource`-typed var (`light.night`) is Variant, so `var x := light.night > 0.2` fails to parse; type it (`var x: bool = ...`).
- `Image.load_from_file("res://x.png")` prints an export WARNING; load the imported `Texture2D` and call `get_image()` (fallback to the raw file only before the first import).
- Style perf (Vulkan, M2 Pro): shadow passes are the main cost of small dressing (wires, frames, grilles: put them on a no-shadow mesh); 40 small omni lights in a narrow lane cost about 2 ms; create night lights only when night >= 0.2; per-area volumetric fog (one FogVolume) about 0.3 to 1.3 ms; the full-screen heat shimmer pass about 1 to 2 ms.
- The first view of a fresh shader set can read a single-digit average fps while pipelines compile (a perf FAIL on car_closeup that a rerun does not show): judge perf on a second run, never the first after a shader change.
- SDFGI on the stand-ins (P0-038, Vulkan): the narrow bazaar lane reads near black by day and stays black after 12 s, with or without the dressing and with occlusion off; SSIL plus sky ambient plus a few soft bounce lights lights it well. Realistic keeps SDFGI opt-in (`--style-off=sdfgi_on`).
- ACES crushed the dark asphalt in shade to black at golden and dawn; the realistic look uses Filmic with exposure x1.25 and ambient x1.8. PhysicalSkyMaterial looked grey against the haze until energy_multiplier 2.2, turbidity 8, mie 0.01.
- Inverse square street lights (spot_attenuation 2) need energy about 170 from a 9 m head to show a pool on dark, damp asphalt under Filmic at night exposure.
- Shader uniforms and local variables share a namespace: a uniform `dust` broke a later `float dust` ("Redefinition"). `get_shader_parameter` returns null for a uniform the material never set, not its default.
- Upscaler test without a new game arg: realistic reads `--style-off=fsr2@0.75` (or metalfx@s) and sets Viewport scaling_3d_mode and scale; FSR 2 replaces TAA. MetalFX needs the Metal driver, which reports no GPU time.
- Godot import "fix_alpha_border" (on by default) bleeds colour into alpha 0 pixels: on a texture whose alpha is a mask (the tile_*.png layers) it smears dark lines into blocky bands (the "swirl cracks" and "marbled" walls of P0-034). Keep it off for mask textures, on only for real transparency (grille).
- Style perf (Vulkan, M2 Pro, bazaar): the sun's PCSS (light_angular_distance > 0) cost about 1.8 ms and directional_shadow_blend_splits about 1 ms; shadow triangles, splits and distance changed nothing measurable. Measure with --style-off tokens before guessing; run to run noise is about 0.5 ms on a calm machine and 2 to 3 ms when another process uses the GPU (check `ps -r` for browsers).
- Tiling textures in surface_b are `source_color`, so samples are linear: a 0.5 sRGB grey reads 0.21, not 0.5 (the asphalt `t.r * 2.0` multiplier is about 0.43 on plain asphalt).
- Look-proof run to run noise (stylised_b, same build, sim held, 1920x1080): golden and night mean diff 0.03 and 0.0% of pixels, afternoon (heat shimmer) 0.65 and 0.2%. `lookproof.mjs --approve` takes one set: golden is `approved/`, the other three lights are compared with `--against style_stylised_b_<light>`. look_rules.json tolerances are mean 1.5, share 1%.
- Per-instance shader uniforms (`instance uniform wear` in surface_b) have room for about 4096 instances (rendering/limits/global_shader_variables/buffer_size 65536, 16 slots each). Measured in P0-016: 5615 MultiMeshes that set wear, or 12000 MeshInstance3D nodes that only use the material, print "Too many instances using shader instance variables". Set wear on a few tile meshes only; instanced modules need another carrier (MultiMesh custom data or a per-area texture), or they draw with wear 0.
- Render bench (P0-016, `harness/reports/arch/render.json` summary, M2 Pro, 1920x1080, Vulkan, look B golden, GPU kept busy): the look alone 3.6 ms GPU (7.9 ms at 2880x1620); a 2 km city of 3877 buildings on MultiMesh cells with visibility range LOD 7.1 ms GPU, 1.2 ms CPU, 1600 draw calls; the same with no LOD 15.5 ms and 10600 draw calls; TAA plus 1.3 ms, MSAA 4x plus 1.55 ms; SDFGI plus 17 ms at 140 km/h (plus 2.4 ms on foot, plus 380 MB); 300 walkers plus 0.4 ms CPU and 0.8 ms GPU as 40 skinned plus baked vertex animation, plus 1.6 and 1.7 ms all skinned.
- Upscaling to 2880x1620 from a 1080p-class render (P0-016): FSR 2.2 costs 5.6 to 6.4 ms and MetalFX temporal 4.6 ms over the plain 1080p frame, MetalFX spatial 1.1 ms, FSR 1.0 1.2 ms, bilinear 0.5 to 0.7 ms. Native 2880x1620 is 14.7 ms. MetalFX is set through `Viewport.scaling_3d_mode` and works on the Metal driver in 4.7.2.
- VRAM compressed import on this Apple Silicon Mac (P0-016): with both project settings off the importer writes S3TC and the game loads S3TC; both sets on adds an ETC2 copy (cache times 2, import 2.8 s against 2.4 s for 30 megapixels); high quality (BPTC plus ASTC) took 63 s and 85 MB. A lossless texture array loads 40 times slower (839 ms against 22 ms) and takes 7 times the video memory (172 MB against 24 MB for one kit).
- A MultiMesh is culled as one box: every instance draws in every shadow split that touches the box (the baked crowd drew 4.0 M primitives against 2.8 M for 300 separately culled rigs). Keep cells small or turn shadows off for far instances.
- Default look (P1-002): with no `--style` the GameArgs autoload makes a stylised_b runner at boot, also under `godot -s` (autoloads load for SceneTree scripts): run_tests.gd calls `GameArgs.stop_style_runner()` first, and a test that makes a runner on the test tree must `stop()` it, or it restyles every node later tests add (stylised_b `_dress` errors). The engine adds the main scene to the tree before the autoloads get `_ready`, so a runner made in GameArgs._ready never sees the boot scene's node_added: GameArgs restyles `current_scene` with `restyle_tree` (earlier style tests only looked right because every view loads a scene). A preloaded script const named like an autoload (`const DayClock := preload(...)`) shadows the singleton and fails to parse: name it `DayClockScript`.
- The day clock rebuilds the style only on a scene load (WorldEnvironment node_added, a move of a game minute or more); a pinned clock (--time, --light) never rebuilds, so look proofs stay byte for byte. Look proof sets of the default look need `--query "time=<h>"` (or light=), else the shots carry the clock's hour at load. The flat look baseline is `--query "style=none"` now.
- The scaffold boot scene (main.tscn) has no kit material keys, so stylised B keeps its plain materials under the hotter exposure: its sand ground reads near white at 15:00 (boot_title, smoke shot). Not part of the signed look.
