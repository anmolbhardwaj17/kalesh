# world-and-map

One line per gotcha.

- src/geo/projection.ts: z is metres SOUTH of the origin (north is -Z), so `geoToWorld` returns negative z for anything north of India Gate; landmarks: Connaught Place park about (-1246, -2062), Red Fort about (+1130, -4800).
- The series projection round trip is about 0.4 mm, not exact: assert round trips under 1 cm / 1e-7 degrees, not 1e-9.
- Godot `Vector2`/`Vector3` are 32 bit floats in the standard build (0.4 mm error at 25 km); `game/geo/projection.gd` returns plain float Dictionaries. Do geo maths in floats, convert to Vector3 only to place nodes.
- `Projection` is a Godot builtin type: a preload const named Projection fails to parse. The port is preloaded as `Geo`.
- Stand-in scenes (game/scenes/standin/): GDScript inner classes cannot call the outer script's static funcs, so the Sink (geo.gd) reaches primitives through `const P := preload("prims.gd")`; geo.gd extends prims.gd so `Geo.extrude()` and `Geo.SEG_ROUND` work outside.
- Godot front faces are clockwise: for an outward face (b - a).cross(c - a) points inward, and a closed outward solid has negative signed volume (checked against BoxMesh in test_standin.gd). prims.gd tri() winds from the normal, so pass the outward normal, never hand-order vertices.
- A Kit.at(p, yaw) frame faces -Z at yaw 0; to face +X use yaw -PI/2, to face -X use +PI/2 (rotating -Z by yaw gives (-sin, 0, -cos)).
- Bake code (`tools/bake/`, P0-018): Node 22 runs the `.ts` files directly, so imports between them carry the `.ts` ending (both tsconfigs have `allowImportingTsExtensions`), no enums or parameter properties, and no Node types (`types: []`): file and network work stays in `.mjs` drivers (`harness/bench/pilot_data/`). Geometry is in district metres, origin at the area centre (`projector(area.centre)`).
- Source fetch (`fetch.mjs`): Overpass answers 406 to curl and Mozilla client names, a plain custom name works; never query `nwr` with `>` (boundary and route relations pull in the country), ask for nodes, ways and tagged multipolygon relations. FABDEM is a 1.9 GB zip per 10 degrees: one tile is read out with byte ranges. GEDTM30 is one global file: geotiff.js `fromUrl` reads a window. Google Open Buildings cell 391 is 6.7 GB of gzip (17 minutes here): streamed once and hashed, only pilot rows kept. `fetch failed` on a licence page is often a passing network fault: run `--only licences` again before calling it unreachable.
- Licences checked 2026-11-11 (table in `harness/bench/pilot_data/licences.mjs`): Microsoft footprints are CDLA Permissive 2.0 now, not ODbL; GEDTM30 v1.2 is CC BY 4.0 but its record says "testing purposes"; FABDEM is CC BY-NC-SA (never shipped). The ASI Delhi list page has no list in its HTML: ASI ids come through Wikidata P1371 (160 ids).
- Height data in the pilot: GEDTM30 read cell by cell is noisy (about 1 m between neighbours, steps to 2.7 m in 15 m along a road); smoothed over 60 m it is the smoothest source. GLO-30 needs the ground filter (`fitGround`). All three files are EGM2008 heights; they differ from each other by 1 to 2 m, so only relative relief is trusted.
- OSM in the pilot: lanes on under 9 percent of road ways, width on under 4 percent, building height or levels on 4 to 19 percent. Rajiv Chowk station is a 25,000 m2 `building=train_station` on layer -2: `buildMap` leaves out footprints below ground. The CP radials are true one-way streets (R-ROAD-04 flags them for review, never auto).
- Overture buildings (BS1) drop the OSM tags wikidata, historic, amenity, religion and addr: the landmark join reads OSM directly. Overture leaves out about half of Google's footprints in dense blocks (the ones sitting on roads); our own merge keeps them and gets 1,858 footprints with a road centre line through them in Chandni Chowk against 7.
- Tiles: `tools/bake/tile.ts` winds triangles clockwise from the outward normal (Godot) and flips them for `.glb`. The T1 file and its GDScript reader (`game/bench/tiles/tile_t1.gd`) are tied by the fixture `harness/data/fixtures/tile_t1_sample.json` (`node tools/fixtures/gen_tile_fixture.mjs` after any format change).
- `data/` is gitignored except the pin list `data/SOURCES.json`. Overrides samples live in `harness/data/overrides/<district>/<tileX>_<tileZ>.json`; `census.mjs --write-sample-overrides` rewrites them from the current issues.
