# Game hook contract (`window.__game`)

The game is Godot 4 (decisions.md 2026-11-10). The same hooks are served by an in-game debug server over TCP: see "Godot transport" below. `window.__game` and the page params describe the browser path, kept for the three.js scaffold until P0-027 and for a later web demo.

What the game must expose so the harness can drive it: verify scenarios, play scripts, shots, look proofs and perf budgets all go through this object. The ADOPT phase adds it to the existing game as its first task. Scenario `hooks_contract` (`harness/verify/scripts/hooks_contract.js`) checks it on every `verify --quick`.

## Rules

- The debug part exists only when the page URL has `debug=1`. Without it, `window.__game` may exist (ready and version only) but `window.__game.debug` must be undefined, and the game plays exactly as before.
- `verify=1` hides every debug overlay (FPS meters, input boxes, inspector panels) so they never appear in shots.
- Hooks drive the game the way a player could (inputs, camera, time) or read it. Play scripts never write positions or flags to skip work; `teleport` exists for staging scenes and look proofs, never inside a milestone play script.
- Every hook returns plain JSON-able data (the harness copies results with `JSON.parse(JSON.stringify(v))`).
- Expected situations never call `console.error`: any console error fails verification.
- Keep the hook code in one folder (`game/debug/` in Godot) and list it in `harness/verify/shared_paths.json`: a change there can break every scenario.

## Godot transport

The Godot game serves every hook from `game/debug/debug_server.gd`. `game/core/game_args.gd` (autoload `GameArgs`) adds it under `/root` as `DebugServer` only when the game starts with the user arg `--debug`. Without it no port opens, no debug node exists and the debug scripts are never loaded (checked by `game/tests/test_debug.gd` and `harness/bin/godotsmoke.mjs`). Client: `harness/bin/godotclient.mjs`.

### Args

Engine args go before `--`, game args after it. The harness always passes `--quit-after <frames>` as a safety net.

```
godot --path game --resolution 1280x720 --quit-after 12000 -- --debug --debug-port=47181 --verify
```

Environment (read by the debug server only): `HARNESS_PARK_WINDOW=1` makes the window borderless and moves it to 30000,30000, outside every display (the harness sets it for every windowed launch so test runs never show a window on the owner's screen; `HARNESS_SHOW_WINDOW=1` on the harness side leaves the window alone, for debugging). A parked window is occluded, so the server force-draws (see `_keep_drawing`).

| Game arg | Replaces | Meaning |
|---|---|---|
| `--debug` | `debug=1` | Starts the debug server. |
| `--debug-port=N` | | Its port on 127.0.0.1. Default 47181 (`kit.config.json` `godot.debugPort`, the same as `DEFAULT_DEBUG_PORT` in `game_args.gd`). The harness picks a free port per run. |
| `--verify` | `verify=1` | Hides every debug overlay (the `DEBUG port fps sim` label). `state().debugOverlay` says if one shows. |
| `--quality=<preset>` | `quality=` | Start preset (low, medium, high). |
| `--style=<name>` | `style=` | The look. Absent: the signed stylised B (`stylised_b`, P1-002; architecture benches with `--arch` keep their own look and default to `none`). `none`: the flat stand-in look, no style code loaded (fast verification; scenarios that do not judge the look use it, see `harness/verify/scenarios.json` `_doc`). Reference sets until the P1 gate: `stylised` (look B), `stylised_grime` (B+D), `realistic`. Restyles every scene through `game/render/style_runner.gd`. `state().style` reports the look id. |
| `--light=<preset>` | `light=` | Pins the day clock to a light preset: `dawn` (6.3 h), `afternoon` (15.0), `golden` (17.75) or `night` (22.0); the look uses the preset itself. |
| `--time=<0..24>` | `time=` | Pins the day clock to that hour on the day-night curve (`game/render/day_cycle.gd`, keys are the light presets); overrides `--light`. Without `--time` or `--light` the day clock starts at 15:00 and runs. `state().time` reports the clock. |
| `--style-off=<a,b>` | `style-off=` | `stylised_b` features to switch off for cost measuring: `volfog`, `shimmer`, `dressing`, `lights`, `textures`, `decals`, `ssao`, `ssil`, `glow`, `sunshadow`; `ssq` keeps the default SSAO and SSIL quality, `nopcss`, `noblend`, `split2`, `near80` and `dshadow` test sun shadow options, and `p34` measures the whole P0-034 setup (no lean path). |
| `--scene=<id>` | | Start in that scene (ids in `GameArgs.SCENES`: `city`, `scaffold`, `course`, and the P0-009 stand-ins `street`, `landmarks`, `areas`). Without it the game starts in `city` (P1-024, `game/scenes/city.tscn`, the project's main scene): the streamed pilot centre with the player in a vehicle at a spawn pin and PlayerMode (F gets out). `scaffold` is the flat test ground (with PlayerMode since P1-024); the stand-in scenes stay for look tests. |
| `--spawn=<pin>` | `spawn=` | The city scene's start (P1-024): a pin of `game/data/spawn_pins.json` (`cp_auto_stand` the default, the auto stand on Janpath south of Connaught Place; `cp_inner_circle`, `ito_flyover_south`, `chandni_chowk_east`, `rajpath_india_gate`). The ring loads round the pin and the pin's vehicle stands on the nearest lane at grade within 60 m going the pin's way. An unknown pin is a log line and the default applies; a pin whose tile is not in the streamed folder (the test block) gives the old start on the longest lane of the tile nearest India Gate, in the scene's car. `state().world.spawn` reports the start. |
| `--arch=<name>[:setup]` | | Architecture bench: loads the bench scene of that name (`GameArgs.ARCH_SCENES`: `render` is `game/bench/render/`, `physics` is `game/bench/physics/`, `tiles` is `game/bench/tiles/`, `roads` is `game/bench/roads/`); the setup after the colon is read by the bench scene (`--arch=render:city+i3+lod`). `state().arch` reports the whole value. Run by `node harness/bench/arch.mjs <name>`. |
| `--fps=<on\|off>` | | The FPS counter (`game/ui/fps_counter.gd`, P1-049). A harness run starts it off so shots do not change; `--fps=on` shows it, `F3` (action `toggle_fps`, sent through `input`) toggles it. Without the arg and outside `--verify` it follows the build (on in development play and test builds, off in a release). |
| `--tiles=<name>` | `tiles=` | The city scene streams `full` without this arg (`test` when `game/world/tiles/` has no index); with it, the city streams that folder, and so does the scaffold (any other scene streams nothing). Streams a baked tile folder into the scaffold scene (`game/world/world_stream.gd` with the streaming core `game/world/streaming/`, P1-019): `test` is the committed test block `game/world/test_tiles/` (9 tiles of the ITO flyover and Connaught Place, 9.8 MB), `full` the gitignored pilot set `game/world/tiles/` (417 tiles, needs `npm run bake -- pilot`; a snapshot or play copy gets it only when it carries `game/world/tiles.hash`), or a `res://` folder. Hides the stand-in ground, loads the ring round the tile nearest to India Gate and stands the car on the longest lane at grade of that tile. `ready` turns true only when the ring round the car is attached with its colliders. An unknown name or a missing folder is a log line and the stand-in ground stays. `state().world` reports it. Not read with `--arch`. |
| `--lockstep` | `lockstep=1` | At most one engine physics frame per drawn frame (`Engine.max_physics_steps_per_frame = 1`), so a loaded machine runs slower and never catches up in bursts. |
| `--mute` | `mute=1` | Master bus muted. |

Resolution is the engine arg `--resolution WxH`. Both `--key=value` and `--key value` work. Args the game does not know are listed in `GameArgs.unknown`, never an error.

### Messages

TCP on 127.0.0.1, newline-delimited JSON (one UTF-8 JSON object per line).

| Direction | Message |
|---|---|
| client to game | `{"id": 7, "method": "state", "args": []}`. `id` is any number the client picks, one per call. `args` is the hook's argument list. |
| game to client | `{"type": "response", "id": 7, "ok": true, "result": ...}` or `{"type": "response", "id": 7, "ok": false, "error": "..."}`. |
| game to client, once on connect | `{"type": "hello", "protocol": 1, "version", "port", "methods": [...], "args": {...}, "ready", "frame", "headless", "renderer": {adapter, vendor, driver, method}}`. |
| game to client, after every drawn frame | `{"type": "snapshot", "frame", "w", "ready", "state", "clock", "hold", "events"}`. `events` holds only the events since the previous snapshot. |

Writes never block a frame (P1-040, `game/debug/debug_peer.gd`): each client has an out queue that the game hands to the socket only as fast as the socket takes it. A client that stops reading is not waited for: while more than 256 KB wait for it, its snapshots are skipped (the next one it gets carries every event since the last one it got, and the newest state), responses and the hello are still queued, and a client 64 MB behind is dropped. `harness/bin/godotsmoke.mjs` checks it with a client that never reads (no frame over 50 ms).

Methods: `ping`, `state`, `clock`, `frames`, `input`, `perf`, `load`, `teleport`, `setCamera`, `timeScale`, `hold`, `events`, `hud`, `shot`, `quality`, `timeOfDay`, `bench`, `stream`, `vehicle`, `foot`, `city`, `traffic`, `gps`, `quit`. Shapes are the ones in "Required" below, with these Godot details:

- `state()`: `{scene, level, milestone: null, player: {pos, heading, speed, grounded}, camera: {pos, dir, fov, override}, hud, debugOverlay, quality, style, light, arch, lockstep, time, frame, world}`. `light` is the `--light` arg as given. `world` is null unless the scene streams a tile folder (the city scene, or `--tiles`): `{folder, bakeHash, indexTiles, tiles (live tiles), loaded: [ids of the live tiles], held (tiles in any state), heldBytes, queue: {reading, waiting, attach, dispose}, ready (the ring round the focus is attached), booted, burst, cap: {tiles, bytes}, errors (one line per refused tile), bad, totals: {read, live, gone, bad, readMsMax, readMsSum}, triangles, colliderTriangles, colliderChunks, lanes, loadMs, spawn: {pin ("" for the old start near India Gate), name, lane, pos, heading, offM}, landmarks: {placed, far, fullDetailCap} (P2-006: the landmark file of the tile folder; all 0 and cap 2 when the folder has none), infra: {tiles, triangles, nodes} (P2-034: the infrastructure kits of the live tiles, `game/world/systems/infra.gd`; all 0 when the folder has no `infra.json`)}`. `time` is the day clock: `{hour (0..24), clock ("15:00"), rate (game hours per sim second), pinned, lookHour (the hour the current scene's light was built for, null with --style=none), light (the look's light id: a preset name, `time 17.75` when pinned or `clock 15.00` when running)}`.
- `input(action, value)`: `throttle` and `steer` are composite (-1 to 1: negative presses `brake` or `steer_left`, positive `throttle` or `steer_right`). Any InputMap action name also works, with a strength 0 to 1 or a boolean. It goes through `Input.action_press`, the way a player's keys do.
- `frames(n)`: answers `{frame}` after n drawn frames (`RenderingServer.frame_post_draw`). Headless (`--headless`, nothing is drawn) a frame ends on `SceneTree.process_frame` instead, for frames, snapshots, load and quit; `perf` and `shot` answer an error there.
- Covered window (P1-047): macOS stops drawing a window that other windows fully cover (Godot's occlusion check), so `frame_post_draw` would stop while the game logic keeps running. The debug server (`_keep_drawing` in `game/debug/debug_server.gd`) notices 3 process frames without a draw and then calls `RenderingServer.force_draw(false)` every frame, so `frames`, `shot`, `perf` and snapshots work whatever is in front; `perf` answers `forcedDraws` (the frames drawn by hand in its window, 0 when the window was visible). Covered numbers are not a real display (no 120 fps cap): take perf with the window visible.
- `perf(ms)`: `cpuMs` is the game logic time of the frame (first physics or process callback to the last `_process`, measured by `game/debug/frame_probe.gd`) plus the viewport's measured render CPU time and frame setup time. `gpuMs` is the viewport's measured GPU time. `p95FrameMs` and `avgFps` come from the intervals between drawn frames. `drawCalls` and `triangles` are the max per frame of `RenderingServer` total draw calls and primitives in frame (`drawCallsAvg`, `trianglesAvg` too). `gpuMB` is video memory used (`textureMB`, `bufferMB` too). On macOS the default Metal driver gives no GPU time, so `gpuMs` is missing and `gpuNote` says why; with the engine arg `--rendering-driver vulkan` (MoltenVK) `gpuMs` is there.
- `perf(ms)` also answers `frameMs: {p50, p95, max}`, the intervals between drawn frames. Read GPU times with care on this Mac: a window is capped at 120 fps even with vsync off (seen since about midnight of 2026-11-11 IST), and under the cap a light scene reads about 6.5 ms of `gpuMs` whatever it costs (most likely the GPU clocks down). `lookproof --perf`, the verify perf gate and the benches keep the GPU busy with a ballast for a true reading (`harness/bin/ballast.mjs`, `bench('ballast')`); `gpuMs` of a plain window stays the capped reading.
- `bench(cmd, opts)`: two commands work in any scene, the rest are for architecture benches (`--arch=<name>`). `ballast` (`{n}`: a constant GPU load of n shader iterations per pixel in an offscreen viewport, `game/debug/gpu_ballast.gd`, 0 is off) and `blank` (`{on}`: the root viewport draws no 3D, so a window measures the ballast alone) give honest GPU readings under the 120 fps cap: `harness/bin/ballast.mjs` calibrates the ballast, reads `gpuMs` with the GPU kept busy and subtracts the ballast alone from the frame times (`gpuCost` in the perf block, used by `lookproof --perf` and the verify perf gate). Every other command goes to the bench scene's `bench_call(cmd, opts)` and is an error response in any other scene. The render bench (`game/bench/render/render_bench.gd`) knows `info` (ready, build time, world counts, viewport settings) and `path` and `pose` (`{name, seconds}` or `{name, t}`: start a camera path or hold a fixed view). The physics bench (`game/bench/physics/physics_bench.gd`) knows `info`, `run` (`{test, ...opts}`: starts one of its tests, which runs over many frames, and answers `{started}`), `poll` (`{test}`: `{running, done, result}`) and `pose` (`{name}` or `{pos, target}` in course coordinates). The tile format bench (`game/bench/tiles/tiles_bench.gd`) knows `info`, `run` (`{test: "load", format: t1|t2|t3, files, loads}`, `{test: "memory", format, files, copies}` or `{test: "free"}`), `poll` and `pose` (`{name}`: `overview` or `street`). The road bench (`game/bench/roads/roads_bench.gd`) knows `info`, `poses` (the pose names of the baked site), `pose` (`{name}`: a top pose looks straight down with north up, an eye pose is a perspective view) and `probe` (a ray down at the bake's probe points: `{points, hits, missing, missingList, maxErrorM}`). Play scripts never use it; the harness uses ballast and blank after a perf window, and the scenario script `relight_live.js` (P1-028) uses them itself so its ballast window falls inside a running change of light (the shim exposes `debug.bench`).
- `load(id)`: changes to the scene and answers `{scene}` two drawn frames later. With `--tiles`, a scene that has the scaffold's car streams the tiles again and the answer waits until the player's ring is attached. Releases debug inputs and the debug camera. Unknown ids are an error response.
- `ready` (hello and snapshots): a frame was drawn, a scene is loaded and, with `--tiles`, the ring round the player is attached with its colliders (`GameArgs.world_ready`). Load time (launch to the first ready snapshot) so includes the first ring.
- `teleport([x, y, z])` or `teleport([x, y, z, heading])`: puts the player on the ground at x, z and stops it (with a fourth number, P2-032, a vehicle turned to that compass heading in radians, 0 north, so a staged drive starts along its lane). On the scaffold y is ignored. In the streamed city it answers only when the ring round the target is attached with its colliders (loaded in a burst: the frame cap is lifted, as under a load screen) and the player stands on the collider there; y above 0 picks the level (the first surface under y + 3 m: a flyover deck or the road under it), y 0 means the top surface. A teleport that a later teleport overtakes while it waits for its ring answers false; the later one places the player. A name looks for a node in the group `anchor` (none yet, so it answers false).
- `stream(cmd, opts)`: probes of the streamed city (`game/debug/stream_probe.gd`, loaded on first use; an error response in a scene with no `--tiles`). `info`: `state().world` plus `path`, `focus`, `speed`, `worstStepMs` and `overBudget` (per system and step kind). `path` `{points: [[x, y, z], ...], speedKmh, loop}`: moves the player along a polyline of world points at a constant speed on the sim tick, heading along it (a scripted drive for perf and memory scenarios only, never in a milestone play script: the V2 vehicle's body is frozen and carried along the path, `vehicle.gd` `carry()`); `{stop: true}` ends it and the vehicle stands there as a physics body again; a finished one-way path emits `stream:path_done`. `record` `{on: true, skipS}` starts recording every drawn frame; `{on: false}` stops and answers `{frames, simS, frameMs: {p50, p95, p99, max} (after skipS), over33, over33List, coreMs (the whole streaming step of a frame), attachMs (the attach queue), chunksMax (collider chunks in one frame, burst frames left out), chunkFrames, meshFrames, mixedFrames (a mesh and a chunk in one frame: always 0), burstFrames, drawCalls: {max, avg}, heldMax, liveMax, capTiles, tilesRead, tilesGone, readMsMax, readMsAvg, worstStepMs, overBudget, path}`; `{}` answers the numbers so far. `probe` `{x, z, y}`: `{hit, colliderY, drawn, drawnY, material, gapM, tile}`, a ray down against the drawn surface read from the tile files (paint, water and deck undersides left out); both look down from y, or from above everything. `mem`: `{objects, nodes, resources, staticMB, rssMB (where ps exists), videoMB, held, live, capTiles, colliderChunks, lanePieces}`. `layers` `{hide: [names], show: [names]}` (P1-026): hides or shows the drawn meshes of a streaming system on every live tile (`ground_roads` the roads and ground, `buildings` the shells; node names `<name>_<tile>`) and answers `{<name>: {meshes, visible}}`; for GPU ablation runs (the per system table, `harness/bin/citybase.mjs`) with a player that stands still, since a tile that streams in later is drawn. `record` also answers `processMs`, `physicsMs` (the engine's TIME_PHYSICS_PROCESS monitor, which refreshes about once a second: read p50 as a mean, not p95) and `renderCpuMs`, each `{p50, p95, p99, max}`.
- `vehicle(cmd, opts)` (P1-020): probes of the player's V2 vehicle (`game/debug/vehicle_probe.gd`, loaded on first use). They drive with the InputMap actions (`Input.action_press`, the way a player's keys do), measure in sim ticks and stage the vehicle with `place()` the way `teleport` does; never in a milestone play script. `info`: `{tune, kmh, heading, gear, contacts, health, settled, scriptUsPerTick, camera: {view, lookingBack, fov}}`. `use` `{id}` (P1-021): the player now drives the vehicle of `game/data/vehicles/<id>.tres` (`car`, `auto`, `scooter`, `patrol_car`), made where the old one stood under the same node name; the chase camera snaps to it in the tune's `camera_view`; answers its `info` (a player choosing a vehicle; staging only, never in a milestone play script). `run` `{test}` (the course scene only, `load('course')`): `straight` (full throttle from rest on the straight, then full brake; `until: "<kmh>"` stops the throttle 1 km/h over that speed, `mark` (100) is the speed of the 0 to mark time, `brakeFrom` (100) the speed the brake distance counts from) answers `{latencyTicks, zeroTo100S, zeroTo100DistanceM, topSpeedKmh, peakSpeedKmh, topReachedAfterS, brakeFrom100M, brakeTimeS, lateralDriftM, markKmh, zeroToMarkS, brakeFromKmh, brakeFromM}` (the 100 keys hold the mark and brakeFrom numbers); `lock` `{kmh}` (full right lock at a held speed, default 38; roll counted from the moment the lock goes on) answers `{heldKmh, radiusM, turnsRight, lateralG, maxRollDeg, flipped, minWheelsInContact}`; `gali` `{kmh, turnAhead, turnZ, releaseDeg, lineOffset}` (P1-021: the course gali's right angle corner between walls, scripted inputs: creep, full right lock at the turn point, out along the east lane) answers `{finished, contactTicks (the collision box with a 2 cm skin against the walls), firstContact, minClearanceM, minClearanceAt, simS, trace}`; `stable` `{straightS, kmh, amp, wave, slalomS}` (P1-021: full throttle on the straight, then a slalom at a held speed) answers `{straight, slalom: {entryKmh, topKmh, maxRollDeg (the physics body), maxLeanDeg (the drawn body), minUpY, minWheelsInContact, maxLateralM}, fell}`; `kerb` (the one-sided 0.15 m kerb at 40 km/h) and `flyover` (the deck joints at 100 km/h) answer `{entryKmh, finished, maxRollDeg, flipped, minKmh, speedLossPct, allWheelsTicksPct, minWheelsInContact, contactLoss, lossTicksBefore, trace}`. `cost` `{n}`: n more cars drive beside the player; answers `{cars, msPerCar (the median physics iteration with them less without, over n; run windowed at time scale 4), scriptMsPerCar, physicsFrameMs, physicsFrameBaseMs}` and prints it. `camrec` `{on: true}` records every drawn frame, `{on: false}` answers `{frames, minAboveM (camera height over the vehicle origin), minDistM, insideFrames (a 0.1 m sphere at the camera touches the world), blockedFrames (the world between a point 1.4 m over the vehicle and the camera), worst}`.
- `state().player` with the V2 vehicle (P1-020): `pos` is where the vehicle meets the ground at rest (its origin less the ride height along its up axis), `heading` the compass heading of its nose, `speed` the speed along it in m/s (a carried vehicle reports the path speed), `grounded` true while a wheel touches or the body is frozen for staging. `teleport` stands it on the ground there frozen; the next tick finds the ground under it and lets it go.
- `city(cmd, opts)` (P1-024): the city checks (`game/debug/city_probe.gd` with `drawn_surface.gd`, loaded on first use; an error response in a scene with no streamed city, except `mirror` and `screen`). Read only: they move nothing. `pins`: the pins of the live tiles `[{id, name, kind, x, y, z, tile}]` (world metres, tile origin plus the pin); a landmark pin (P2-006: kind `landmark`, id `lm:<registry id>`) also has `tier`, `mode` (`structure`, `site` or `point`), `yaw` (the compass bearing its front faces, 0 north, 90 east) and `height`, and `underground` or `worship` when true. `landmarks` `{at: [x, z], limit}` (P2-006): the landmark file of the tile folder (`landmarks.json`): `{limits: {heroesAtFullDetailInView, farSilhouetteTriangles, heroLods}, placed, silhouettes, far: [{id, pos, bearing, distance, reachable: false, nav: false}], heroesAtFullDetail, plan: [{id, tier, level, distance}]}`: the LOD slot each landmark shows from `at` (the camera when left out), nearest first, `level` -1 for the far silhouette (`game/world/landmark_slots.gd`: at most 2 heroes at level 0). `geo` `{places: [{id, lat, lon}]}`: where the game's projection puts each place, `[{id, x, z}]` (the world frame of the loaded index plus `game/geo/projection.gd`). `screen` `{points: [[x, y, z]]}`: `{size: [w, h], points: [{x, y, front}]}`, where the current camera draws each point (pixels from the top left; `front` false behind the camera). `mirror`: every Node3D under the scene's `World` (a negative scale component, a mirrored local or global basis), every MultiMesh instance and every streamed collider body (physics server bodies with no node, read with `body_get_state`): `{nodes, instances, bodies, bad: ["<path>: <why>"], more}`. `kit` `{visible, at: [x, z]}` (P2-007): the parts kit landmarks (`game/world/systems/landmarks.gd`): `{ready, building: [ids], shown, far (backdrop silhouettes drawn), landmarks: [{id, tier, recipe, source ("kit" or "model": a delivered hero model replaced the stand-in), built, pos, registryHeightM, heightM (the built height of the part the registry height measures), heightPart, topM, heightErrPct, triangles (per level 0, 1, 2 and the far silhouette), maxPartTriangles (the heaviest part per level), parts, colliders, buildMs, ranges ([from, to] m per level), distance (from `at`, else the camera), level (shown there; -1 far, -2 none), worship, combatArena (false for a place of worship, else null)}]}`; `visible` false hides every landmark the system draws (the landmark GPU cost is the frame with them minus without, scenario `landmarks_two_heroes`), true shows them. `surface` `{points: [[x, z]]}`: per point a ray down from above everything against the tile colliders (mask 1; the parts kit landmarks' own colliders, group `landmark_kit`, are left out: the tile files hold only their ground) and the highest drawn surface of the tile files there (paint, water and deck undersides left out): `[{x, z, hit, colliderY, drawn, drawnY, material, gapM}]`. `watch` `{on: true}` starts a per-sim-tick record of the player against the drawn surface (driving: every wheel contact of the step, `vehicle.gd wheel_contacts()`; on foot: the feet on every grounded tick) to the nearest drawn height at that point; `{on: false}` stops it and `{}` reads it: `{ticks, samples, over (contacts more than 0.05 m off), maxGapM, worst: {x, y, z, drawnY, material, tick}, undrawn (contacts with nothing drawn there), airTicks (no contact), fallTicks (the feet 0.5 m or more under the highest drawn surface within 3 m above them), fall, foot, vehicle (ticks in each mode), readMs, bodyTicks, body}`; driving, `bodyTicks` counts the ticks the vehicle's body box (2 cm skin) touches a collider more than 0.35 m over the wheel contacts (a wall or a ceiling, P2-032; a touch on an upward face, the body grounding on a crest, counts in `groundTicks` instead), `body` the first: `{x, y, z, tick, contactY, overWheelsM, local: [x right, y up, z back] on the body, point, normal}`.
- `teleport([x, y, z])`: puts the player on the ground at x, z and stops it. On the scaffold y is ignored. ### Snapshot vs request

`state`, `clock`, `hold` (read) and `events` are cheap and change every frame, so the game pushes them in each snapshot. A driver answers the synchronous hooks from the newest snapshot (the harness-side event ring is the events of every snapshot it got). The harness driver (`harness/bin/godotdriver.mjs`, VERIFY.md "Godot runs") runs page-side scripts in a node vm with a `window.__game` shim built this way (`harness/bin/godotshim.mjs`). `frames`, `perf`, `load`, `shot`, `input`, `teleport`, `setCamera`, `timeScale`, `hold({...})`, `hud`, `quality`, `timeOfDay` and `quit` are requests: the answer comes in the response.

### Sim clock and hold

`game/core/sim_clock.gd` (autoload `SimClock`, C1 since P1-006) owns sim time for every system that steps: they connect to `SimClock.sim_tick(dt)` and step only there. One engine physics frame is one tick of exactly 1/60 s, so `t` is always a whole number of ticks. `timeScale(n)` sets `Engine.time_scale` and `Engine.physics_ticks_per_second` together (n 4 runs 240 physics frames per real second, n 0.25 runs 15; each still steps 1/60 s of sim and of physics); n 0 runs no ticks and stops the physics server, at the engine rates of n 1. `hold({at})` pauses on the last tick boundary at or before `at` (within one tick, never past it) and emits a `sim:hold` event. A held sim runs no ticks and the physics server is stopped (`PhysicsServer3D.set_active(false)`, only at the start of a physics frame, so a running tick keeps its step); frames keep drawing, and a release resumes exactly (an input script held and resumed ends within 0.0000 m of one never held, `game/tests/test_sim_clock.gd`). `clock().scale` is the scale as asked.

### Errors

Expected problems (unknown method, bad args, unknown scene or action) are error responses, never `push_error`. Unexpected engine or script errors are caught by `game/debug/debug_logger.gd` (a Godot `Logger`) and sent as `error` events `{kind, message, code, function, file, line}`, so they show in the snapshot `events`. Godot still prints them as `ERROR` lines, which `godot.mjs` and the smoke test fail on.

### Smoke test

`node harness/bin/godotsmoke.mjs` (add `--driver vulkan` for GPU times) runs the game without `--debug` and checks no port listens, then windowed with `--debug --verify`, calls every hook, checks each shape and the hold, saves `harness/reports/godot/smoke_shot.png` and writes `harness/reports/godot/smoke.json`.

## Page params (browser, the web demo path, later)

| Param | Meaning |
|---|---|
| `debug=1` | Turns on `window.__game.debug`. |
| `verify=1` | Hides debug overlays; the harness always sets it (kit.config.json `pageQuery`). |
| `quality=<preset>` | Starts on that quality preset (low, medium, high, or the game's names). Scenarios with `quality` use it; perf budgets are per preset. |
| `lockstep=1` | Optional. Every rendered frame runs a fixed slice of sim, so a loaded page runs slower instead of catching up in bursts. Use for scenarios whose script steers or reads AI timing. |

| `light=<preset>` | With `style`: the light preset (`afternoon`, `golden`). |
| `mute=1` | Optional. Master volume 0 (a negative control for audio checks). |

## Optional (used when present)

| Hook | Used by |
|---|---|
| `shotProblems(name): string[]` | Every shot: what is wrong on screen now (the player under the HUD, a subtitle over the player, a debug overlay on). Each string fails the step. |
| `gpuBench({ n, reps }): number[]` | `gpucost.mjs`: draws the current frame n times between GPU syncs, reps times, and returns ms per rep; the stable GPU cost replaces the noisy timer p95 in the frame time gate. |
| `quality(name?)` | Read or switch the quality preset at run time. |
| `save(op, data?)` | Read, write or clear the save for persistence checks. |
| `timeOfDay(opts?)` | Read or set the day clock `{hour, rate, pin, reload}` (Godot details above); `hooks_contract` checks it. |
| `ui(what)` | UI state for menu and transition checks (for example `ui('transition')` gives the current phase: loading, card, play). |

## How each harness number is measured

| Number | Source |
|---|---|
| Load time | page open to `ready === true` (verify.mjs), judged by `perf_budgets.json loadMs`. |
| Frame time p95 | `perf(ms).cpuMs.p95` and `gpuMs.p95` (or the gpuBench cost), the larger counts (`perfgate.mjs`). |
| fps | `perf(ms).avgFps`, secondary: the display caps it. |
| Draw calls, triangles | `perf(ms).drawCalls`, `.triangles`. |
| GPU memory | `perf(ms).gpuMB`, or `textureMB + renderbufferMB`. |
